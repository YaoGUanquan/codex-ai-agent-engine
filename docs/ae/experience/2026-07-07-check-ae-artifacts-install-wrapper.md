# Check AE Artifacts Install Wrapper Experience

## Context

After updating AE in another project, external testing found that `ae-tools help` advertised `node scripts/check-ae-artifacts.mjs [--target <project>]`, but the target project did not contain that script. Running the advertised command failed with `MODULE_NOT_FOUND`.

## Root Cause

`scripts/check-ae-artifacts.mjs` existed only as a repository-level script. The project installer generated wrappers for selected helper commands such as `ae-tools`, `set-ae-language`, and `check-design-contract`, but did not generate a `check-ae-artifacts` wrapper. The plugin package also did not contain `plugins/ai-agent-engine-codex/scripts/check-ae-artifacts.mjs`, so installed projects could not import a packaged implementation.

## Decision

Use the established standalone helper distribution pattern:

- packaged implementation: `plugins/ai-agent-engine-codex/scripts/check-ae-artifacts.mjs`;
- repository wrapper: `scripts/check-ae-artifacts.mjs`;
- installed project wrapper: generated by `scripts/install-project.mjs`;
- install smoke proof: path existence plus actual target-project execution.

Do not remove the command from the help catalog because it is a useful validation command and many docs already reference it.

## Validation

```powershell
npm test -- --test-name-pattern "check-install-smoke reports ok"
npm test
npm run check
node scripts/check-ae-artifacts.mjs
node plugins/ai-agent-engine-codex/scripts/check-ae-artifacts.mjs
git diff --check
```

The targeted test failed before the fix because `verifiedCommands` did not include `check-ae-artifacts`, then passed after the wrapper and smoke coverage were added. Full validation passed on 2026-07-07.

## Reusable Lesson

Help/catalog entries are distribution claims. If a command is listed as `node scripts/<name>.mjs`, install smoke must prove the installed target has that path and can execute it from the target root. Repository-only script existence is not enough.
