# Security Scan Records

Store only two user-facing record types in this directory: a sanitized scan summary and one remediation report. The remediation report begins as a local `draft`, records the user's exact approval, then becomes `approved-for-execution`, `executed`, and `reconciled` without being replaced by another report. PRDs, plans, reviews, and test evidence remain supporting engineering artifacts rather than additional delivery reports.

The sanitized report inventory has one row per source finding. During local source verification, assign each row a human-verified `canonicalCaseId` in the remediation report. Do not use raw scanner IDs, finding counts, complete coverage, or zero findings as proof that a case is fixed. A post-remediation scan records separate configuration and snapshot data, links findings through those canonical cases, and lists every unmatched new finding as `new-untriaged`.

The remediation report is an explicit approval gate. No source change may enter `ae-work` until the user has inspected and approved the exact local draft scope, proposed changes, validation, and rollback signals. Any material change invalidates approval and requires a new approval record. After execution, independent review, local validation, and a fresh approved rescan, use `pass`, `pass-with-accepted-risk`, or `fail`; missing evidence, incomplete coverage, configuration/snapshot mismatch, unaccepted residual risk, or a `new-untriaged` item cannot be a clean pass.

Complete original, unredacted Codex Security CLI artifacts, such as report Markdown, findings JSON, SARIF, coverage output, manifests, logs, and source excerpts, may be stored locally in `.private/<scan-id>/` only after the user explicitly authorizes that retention choice and the directory is confirmed as Git-ignored. A target project must add that ignore rule through its own approved change; plugin installation does not alter `.gitignore`. Read them only when the user explicitly asks to inspect or remediate a prior scan, and never paste them into chat, normal documentation, commands, commits, or tracked paths. Retrieval does not require a rescan; rescan only validates code after remediation. Do not deliberately put credentials or provider URLs there. The directory is intentionally excluded from Git and is not a credential store; it must not be treated as a backup or shared artifact store.
