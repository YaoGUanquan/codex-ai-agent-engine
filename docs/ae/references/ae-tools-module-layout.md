# AE Tools Module Layout (0.3.20+)

This reference describes the post-split layout of `plugins/ai-agent-engine-codex/scripts/ae-tools/`. It is a **maintainer contract**, not a persisted shallow graph snapshot. For runtime dependency previews use `node scripts/ae-tools.mjs ae-graph-query --root plugins/ai-agent-engine-codex/scripts --path ae-tools.mjs --no-write`.

## Entry

| Path | Role |
| --- | --- |
| `scripts/ae-tools.mjs` (repo root wrapper) | Thin import of plugin dispatcher |
| `plugins/ai-agent-engine-codex/scripts/ae-tools.mjs` | Command dispatch + `globalInvocation` only (~120 lines) |

## Layered local imports (DAG)

```text
utils.mjs          (foundation: zero local imports)

yaml.mjs ──► utils
git.mjs  ──► utils

evidence.mjs ──► git, utils
graph.mjs    ──► git, utils
swagger.mjs  ──► yaml, utils
claude.mjs   ──► utils
markitdown.mjs ──► utils
static-server.mjs ──► utils
init.mjs     ──► utils  (+ external init-templates/*.md)
help.mjs     ──► utils
recovery.mjs ──► utils
gate.mjs     ──► utils

tasks.mjs  ──► graph, yaml, utils
review.mjs ──► evidence, git, graph, utils
```

## Init templates

- Directory: `plugins/ai-agent-engine-codex/scripts/ae-tools/init-templates/{en,zh-CN}/`
- Fifteen template keys per language (`agents.md`, `aeReadme.md`, …)
- Placeholders: `{{name}}`, `{{descriptionLine}}`, `{{indicators}}`, `{{importantPaths}}`, `{{scripts}}`
- Render path: CRLF normalized at read time so checkout line endings cannot change generated bytes.

## Regression guards

| Guard | Location |
| --- | --- |
| Acyclic module import graph | `tests/ae-tools.test.mjs` — `ae-tools command modules stay an acyclic layered import graph` |
| Syntax of all `.mjs` under scripts/tests | `scripts/check-syntax.mjs` via `npm run check:syntax` |
| Install smoke after plugin changes | `npm run check:smoke` |

## Rules for new commands

1. Add a new module under `ae-tools/` or extend the smallest existing module; do not grow the dispatcher beyond routing.
2. Import only from lower layers; never import `review.mjs` or `tasks.mjs` from foundation modules.
3. Shared non-command helpers belong in `utils.mjs` unless they are domain-specific to one command family.
4. Distributable plugin changes require synchronized SemVer in root `package.json` and `plugin.json` plus README release notes.
