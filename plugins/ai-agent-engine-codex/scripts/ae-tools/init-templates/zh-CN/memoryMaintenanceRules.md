# AI 记忆维护规则

## 读取规则

- 先检查 `00-index.md` 大小，最多 4096 UTF-8 字节、80 行；超预算不整篇读取，用 `ae-memory-index` 审计。
- 优先用 `ae-memory-search --query "<关键词>" --limit 5` 返回路径、行号和短摘录，再读取命中附近必要内容；不要一次加载 03/04/05 全文。
- 用 `--path` 缩小范围；`--history` 只查旧索引分片。截断或 `scan.complete=false` 不是完整搜索或无匹配证据。
- 已登记的主题/关系仍用 `ae-memory-query`；不把全文搜索冒充声明式关系。
- 外部文档先解析当前项目和分支，显式传 `--docs-root`，不自动混读仓库和外部资料。

## 更新规则

- 只写入稳定、长期有效、可复用的信息。
- 优先更新现有主题文件，主题明显独立时再新建文件。
- 不写入一次性日志、原始命令输出或未确认猜测。
- `00-index.md` 只保留少量领域导航和检索入口，禁止追加日期日志、发布状态、SQL、任务总结和经验正文；导航超预算时分组，不截掉历史。

## 任务结束规则

- 每次任务完成后判断是否形成新的稳定知识；只有用户要求更新记忆时才写入。
- 若获授权，更新最相关的最小专题文件，并在最终说明中列出。
- 若没有，明确说明本次无需更新 AI 记忆库。

## 体积与蒸馏预算

- `ae-memory-index --check` 对入口 4096 字节/80 行和专题 15360 字节执行非零退出门禁；每次记忆更新后运行。
- 单个专题超过 15KiB 时先蒸馏或拆分；稳定规则留专题，历史证据放经验/归档，通过指针追溯。
- 旧索引先用 `ae-memory-index --compact` 预览；仅授权后加 `--apply --expect-sha256 <预览哈希>`。工具先写入并核验同目录有界分片，再替换入口；按序拼接并核验源哈希可恢复。不会自动清理分片或改写其他专题。
- 分片是历史片段，不是独立重新编排的 Markdown 文档；跨页锚点和引用定义需人工复核，不改变原有语义有效性。
- `05-decision-log.md` 按年轮换：新一年开新文件或把上一年条目归档到 `docs/99-archive/`，并同步 `00-index.md` 与 `00-registry.json`。
- 每季度按 `00-registry.json` 的 `reviewStatus` 盘点一次：确认仍然有效的条目，过期主题先蒸馏再归档。
- 已退役功能的主题文件移入归档，不留在记忆库根目录。

## 文档生命周期

- 用 `ae-docs-maintain --check` 覆盖记忆、开发历史、索引和滚动问题/修复台账；`--path <docs相对文件> --compact` 预览，授权后用 `--expect-sha256 <哈希>` 应用。
- 托管文件保持短入口，`ae-docs-append --path <文件> --entry <记录.md>` 自动生成有界分片，应用必须提供源文件和记录两项哈希；不编辑不可变分片或向托管入口追加。
- 用 `ae-docs-search --path <文件> --query "<关键词>"` 检索并按返回路径/页号/行号续查；原记忆检索自动跟随托管专题，旧 `--history` 仍只查旧索引分片。
- 分页保留原始字节和相对链接基准，不保证跨页锚点或语义仍有效。正式文档、SQL、测试数据、JSON registry 和 JSONL 证据链不自动拆改。
